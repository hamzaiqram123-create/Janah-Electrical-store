# The store as an app on every device

The store installs as an app on phones, tablets and computers. It's a Progressive Web App (PWA), built
from the same code as the website, so there is nothing separate to build or update. When the site is
redeployed, every installed copy picks up the new version on its next start.

The back office installs as a **second app** with its own icon (graphite with the conductor-colour
stripe). It's useful as the point of sale on a counter tablet, or on staff phones for orders and stock.

## What customers get

- A home-screen or desktop icon: copper plate with a graphite bolt, the same mark as the site header.
- The app opens full-screen, without the browser's address bar. The header colour runs into the status bar.
- Long-pressing the icon on Android, or right-clicking it on Windows, offers shortcuts: Cart, Track
  order, Categories, Offers. The back-office app offers Point of sale, Orders and Stock.
- Pages they have already opened still work without a connection, and a clear notice says they're
  offline. Ordering and payment always need the internet.
- A back button in the header on inner pages. iPhones have no browser back button in app mode.
- The app opens in the language the customer installed it from: Arabic, English or Urdu.

The site offers the app in three places. None of them appear once the app is installed:

- **Phones:** a small banner above the bottom navigation, shown after the visitor has browsed a little.
  It never appears on the cart, checkout, product or sign-in pages. "Not now" hides it for 30 days.
- **Every device:** a "The store app" block in the footer.
- **Phones:** an "Install the app" row in the side menu.

## How to install, per device

| Device | Browser | What the customer does |
|---|---|---|
| Android phone or tablet | Chrome, Samsung Internet, Edge | Tap **Install** in the store's banner or footer, then **Install** in the dialog. |
| iPhone / iPad | Safari (and Chrome/Edge on iOS 16.4+) | Tap **Install**: the store shows three steps, **Share → Add to Home Screen → Add**. Apple doesn't let websites open an install dialog. |
| Windows, ChromeOS, Linux | Chrome, Edge | **Install the app** in the footer, or the install icon in the address bar. The app appears in the Start menu or app launcher. |
| Mac | Chrome, Edge | Same as Windows. |
| Mac | Safari 17+ | Menu **File → Add to Dock**. The footer button explains this. |
| Any | Firefox | Firefox doesn't install web apps on desktop. The site works normally in the browser. |

The site must be served over **HTTPS** for any of this to work. Render, and any proper hosting, does that.

## Offline behaviour

The service worker (`/sw.js`) is generated by the server for every deploy:

| What | Strategy |
|---|---|
| App code and styles (`/assets/*`) | Downloaded at install, then served from the device. Replaced automatically after a deploy. |
| Product photos and icons | Kept after first view (up to 300 files). |
| Catalogue pages: home, listings, categories, brands, products, FAQ, policy pages | Always fetched fresh. The last 60 visited are kept for offline viewing. |
| Cart, checkout, account, orders, invoices, sign-in, tracking | **Never stored.** Offline, the customer sees the offline page. |
| API calls (prices, stock, cart, payments, admin) | Always from the network. |
| Anything else while offline | `/offline.html`, a short trilingual "you're offline" page. |

Signing out (store or back office) deletes the stored pages, so nothing personal stays on a shared device.

## Android app file (.apk)

`android/` is a small Android project: a Trusted Web Activity that opens the store full-screen in the
phone's browser engine, with a WebView fallback for phones without one. GitHub builds it.

- **Where to get it:** the repository's **Releases** page, e.g.
  `https://github.com/hamzaiqram123-create/Janah-Electrical-store/releases`. Download
  `janah-alriyadah-<version>.apk` on the phone and open it. Android asks once to allow installs from
  that browser or file manager.
- **What it opens:** the address in `android/twa.json`
  (`janah-alriyadah-store.onrender.com`, the Render service name in `render.yaml`). The store opens in
  the phone's language (Arabic, English or Urdu). The launcher name and adaptive/themed icons follow the
  brand.
- **New build:** any push that changes `android/`, or *Actions → Android app → Run workflow*. When the
  store moves to its own domain, change `host` in `android/twa.json` and push.
- **Full screen without an address bar:** set on the server `ANDROID_APP_PACKAGE=sa.janah.store` and
  `ANDROID_APP_SHA256=<fingerprint>`. The fingerprint is printed in each release's notes. Until then
  Android shows a thin address bar above the store.
- **Signing:** with no repository secrets, each build is signed with a new temporary key. That's fine for
  trying the app, but installing a newer build means uninstalling the old one first, and each build has
  a different fingerprint. For a permanent key:
  ```bash
  keytool -genkeypair -keystore janah.jks -alias janah -keyalg RSA -keysize 2048 -validity 10000
  base64 -w0 janah.jks    # → secret ANDROID_KEYSTORE_BASE64
  ```
  Add the secrets `ANDROID_KEYSTORE_BASE64` and `ANDROID_KEYSTORE_PASSWORD` under GitHub **Settings →
  Secrets and variables → Actions**. Keep `janah.jks` and its password safe: they're needed for every
  future update.
- **Google Play:** each release also has the `.aab` that Google Play takes. The app targets Android 16
  (API level 36), as Google Play requires. Publishing steps: [STORES.md](STORES.md#google-play).

## Publishing in the app stores (optional)

Installing from the website already works on every device without any store. Store listings add
discoverability and the familiar "Get it on Google Play" and "Download on the App Store" path.

This repository has a native app project for each store: `android/` (Google Play), `ios/` (App Store,
built and uploaded from GitHub without a Mac) and `desktop/` (Windows installer). The listing texts,
graphics, form answers and step-by-step instructions are in [STORES.md](STORES.md).

Inside these apps the website knows it's running in the shop's own app. They open it with
`?source=android|ios|windows` and add `JanahApp/<version> (<platform>)` to the user agent. So the site shows
no "install the app" offers there, and inner pages get the in-page back button.

## Files and settings

| Path | Purpose |
|---|---|
| `src/server/pwa.ts` | Manifests (`/manifest.webmanifest`, `/admin.webmanifest`), the service worker, the offline page, `assetlinks.json`, the `<head>` tags for iOS/Android |
| `src/web/lib/pwa.ts` | Registers the service worker; install prompt, iOS detection, app mode, connection state |
| `src/web/parts/InstallApp.tsx` | Install banner, footer block, menu row, iOS steps, offline notice |
| `public/icons/` | App icons, generated by `bun scripts/icons.ts` |
| `public/screenshots/` | Phone and desktop screenshots shown in Android's and desktop Chrome's install dialog. Retake them when the design changes (390×844 at 2×, 1280×800 at 1.25×, WebP). |
| `ANDROID_APP_PACKAGE`, `ANDROID_APP_SHA256` | Google Play verification (above) |

App name and description come from **Admin → Settings → Store** (name and tagline per language), so
renaming the shop renames the app.

## What was tested

In Chromium at phone, tablet and desktop sizes:

- Chrome's own installability check (DevTools protocol) reports both apps installable, and both
  manifests parse without errors.
- The service worker installs, precaches the app code and takes control.
- With the server unreachable: a visited product page opens from the device, the cart and an unvisited
  page show the offline page, and in-app navigation ends on the offline page instead of an error.
- The offline notice appears when the device reports no network.
- The install banner appears after browsing and opens the browser's install dialog. On an iPhone
  user-agent it shows the Add to Home Screen steps. "Not now" is remembered. In app mode there are no
  install offers and the back button works.
- Signing out clears the stored pages.

The Android build (`android-v1.0.1`) was built on GitHub and checked:

- `apksigner verify` passes, with an APK Signature Scheme v2 block.
- The package is `sa.janah.store`, with Arabic, English and Urdu names and start pages, and the
  site-verification statement.
- The checksum matches the published `.sha256`.

Not tested here: installing on physical Android, iPhone, Windows and Mac devices, and the store
packaging steps. Those need the live HTTPS site.
